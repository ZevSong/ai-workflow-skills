# 需求不完整时的处理

材料类型：手工编写的预期行为示例；未运行登录系统开发或业务测试。

## 输入

```text
使用 $plan-agent-tasks，把“给应用增加登录功能”拆成任务，生成各会话的启动提示词。
目前还没有确认登录方式、使用者范围和验收标准。
```

## 预期行为

Agent 可先读取现有仓库的认证入口和项目规范，确认已有技术事实；然后集中提出无法从资料确定的需求决定，例如：

| 缺少的决定 | 影响 | 需要用户决定 |
| --- | --- | --- |
| 登录方式 | 页面、接口及外部服务依赖 | 使用已有身份提供方、用户名密码或其他方式 |
| 使用者范围 | 身份与权限边界 | 仅个人、团队还是外部用户；是否需要不同权限 |
| 登录后的成功与拒绝行为 | 可观察验收条件 | 成功后进入哪里，失效/拒绝时显示什么 |

此时不生成带假定结论的正式任务卡，不创建 Worker/Reviewer，不把函数命名或目录细节转交用户决定。用户回答后，只复核受影响的缺口并继续本次显式调用。

## 验收要点

- 输出说明了缺口及其影响。
- 能查明的事实先查明；关键产品决定没有被猜测补齐。
- 没有凭空生成可执行任务、测试通过或会话已启动的结论。
